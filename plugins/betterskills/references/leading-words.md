# Leading Words

Established terms that carry a body of practice in one word. Use them to
replace explanation (R2). Extend this list from the domain of the skill
under review — every field has its own.

## Thinking and deciding

| Term | What it recruits |
|---|---|
| **Design tree** | Decisions as branches that open further decisions; work it in rounds. |
| **Frontier** | The decisions whose prerequisites are already settled — the only ones ready to make now. |
| **Steelman** | State the strongest version of the opposing case. |
| **Premortem** | Assume the effort already failed; explain why. |
| **First principles** | Rebuild the answer from fundamentals, not analogy. |
| **Five whys** | Ask why repeatedly to reach a root cause. |
| **Root cause analysis** | Fix the cause, not the symptom. |
| **Second-order effects** | Consequences of the consequences. |
| **Reversible / one-way door** | Decide fast when reversible, carefully when not. |
| **YAGNI** | Build nothing the current requirement does not need. |
| **Socratic** | Teach by questions; withhold the answer. |
| **Grill / relentlessly** | Persist in challenging a plan until every branch is resolved. |

## Writing and communicating

| Term | What it recruits |
|---|---|
| **BLUF** | Bottom line up front: conclusion first. |
| **Pyramid principle** | Answer first, then grouped supporting arguments. |
| **SCQA** | Situation, complication, question, answer. |
| **Plain language** | Short words, active voice, one idea per sentence. |
| **Inverted pyramid** | Most important information first, detail later. |
| **TL;DR** | One-line summary before the body. |

## Planning and goals

| Term | What it recruits |
|---|---|
| **SMART goals** | Specific, measurable, achievable, relevant, time-bound. |
| **MoSCoW** | Must, should, could, won't prioritisation. |
| **Definition of done** | The explicit checklist that ends a task. |
| **Acceptance criteria** | Testable conditions a change must meet. |
| **Vertical slice** | A thin end-to-end increment, not a layer. |

## Discovery and research

| Term | What it recruits |
|---|---|
| **SPIN discovery** | Situation, problem, implication, need-payoff questions about pain points. |
| **Jobs to be done** | What the user is hiring the product to do. |
| **Five-whys interview** | Dig under the stated need. |
| **Triangulate** | Confirm a claim from independent sources. |

## Engineering

| Term | What it recruits |
|---|---|
| **Refactor** | Change structure without changing behavior, in small safe steps. |
| **Red-green-refactor** | Failing test, minimal pass, then clean up. |
| **Tracer bullet** | A thin working path through every layer first. |
| **Minimal reproduction** | The smallest input that still shows the bug. |
| **Bisect** | Halve the search space until the cause is isolated. |
| **Idempotent** | Safe to run twice. |
| **Fail fast** | Stop at the first error with a clear message. |
| **Boy-scout rule** | Leave touched code cleaner than you found it. |
| **Code smell** | A surface sign of a deeper design problem. |

## Finding new ones

Ask: "Is there an established framework or term for what I'm
describing?" Good candidates appear in textbooks, standards, and
professional jargon. Reject a term the model would have to be taught —
that is a coined word, and it fails R2.b.
